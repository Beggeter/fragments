# План перехода эффекта Whirlwind (LoadingSpinner) на Canvas

## 1. Анализ текущей реализации
- Эффект реализован через компонент LoadingSpinner.
- Для каждой строки поля создаётся компонент Line, который анимирует массив motion.img (цветные svg-клетки).
- Анимация реализована через framer-motion (motion.div, motion.img), параметры анимации — через keyframes, useMotionValue, useTransform.
- Для синхронизации с логикой игры используются колбэки onLineBreakpoint и onFinish.

## 2. Цели перехода
- Перенести всю анимацию с DOM/motion.div/motion.img на canvas.
- Снизить нагрузку на DOM и React, повысить производительность.
- Сохранить/улучшить визуальное качество эффекта (цветные клетки, траектории, взрыв, масштабирование, вращение, fade-out).
- Сохранить API: onFinish, onLineBreakpoint, width/height.

## 3. Новый компонент: WhirlwindSpinnerCanvas
- Рендерит <canvas> поверх игрового поля (position: absolute, pointer-events: none, z-index: ...).
- Все клетки и их анимация реализуются внутри canvas через requestAnimationFrame.
- onFinish вызывается по окончании анимации, onLineBreakpoint — при прохождении очередной строки.

## 4. Структура данных
- Для каждой линии хранить массив клеток (цвет, параметры анимации: xSpread, rot, scale, ...).
- Для каждой линии хранить параметры анимации (startY, topBounce, bounce1, bounce2, finalY, flyDuration, totalDuration).
- Для каждой клетки — текущие значения (позиция, масштаб, поворот, прозрачность).
- Для каждой линии — прогресс анимации (от 0 до 1), время старта.

## 5. Генерация клеток и линий
- При активации эффекта генерировать массив линий и клеток с теми же параметрами, что и сейчас (цвета, xSpread, rot, scale, ...).
- Для каждой линии — свои параметры bounce, flyDuration, totalDuration.

## 6. Анимация
- На каждом кадре (requestAnimationFrame):
  - Очищать canvas.
  - Для каждой линии:
    - Вычислять текущий прогресс (t = (now - startTime) / totalDuration).
    - Для каждой клетки:
      - Вычислять текущие параметры (позиция, масштаб, поворот, прозрачность) по keyframes (интерполяция).
      - Рисовать svg-образ клетки (или canvas-rect с цветом, или отрисовать svg через offscreen canvas).
    - При достижении очередной строки — вызывать onLineBreakpoint.
  - Когда все линии завершили анимацию — вызвать onFinish.

## 7. Визуализация клеток
- Для простоты можно рисовать клетки как цветные прямоугольники с border-radius (или circle), либо использовать offscreen canvas для рендера svg.
- Для плавности — реализовать масштабирование, вращение, fade-out через canvas API (save/restore, translate, rotate, scale, globalAlpha).

## 8. Оптимизация
- Использовать devicePixelRatio для четкости на retina-экранах.
- Минимизировать количество объектов в памяти (все данные — в useRef, не в useState).
- Очищать ресурсы (отменять animationFrame при размонтировании).

## 9. Интеграция
- В GameBoard заменить <LoadingSpinner ... /> на <WhirlwindSpinnerCanvas ... />.
- API и пропсы должны совпадать, чтобы не менять остальной код.
- Убедиться, что onFinish и onLineBreakpoint вызываются корректно.

## 10. Тестирование
- Проверить визуал на всех размерах поля.
- Сравнить с текущей реализацией (цвета, траектории, масштаб, fade, взрыв).
- Проверить производительность на мобильных/старых устройствах.

## 11. Типовые проблемы и их решения

**Проблема 1: Canvas нечеткий на retina-экранах**
- Решение: canvas.width/height = ... * devicePixelRatio, ctx.setTransform(dpr, 0, 0, dpr, 0, 0).

**Проблема 2: Сложно реализовать svg-иконки клеток**
- Решение: Можно рисовать клетки как цветные прямоугольники/circle через fillRect/arc, либо использовать offscreen canvas для рендера svg (или Image).

**Проблема 3: Сложно реализовать сложные анимации (scale, rotate, opacity)**
- Решение: Использовать ctx.save(), ctx.translate(), ctx.rotate(), ctx.scale(), ctx.globalAlpha для каждой клетки.

**Проблема 4: Сложно синхронизировать брейкпоинты (onLineBreakpoint)**
- Решение: Для каждой линии хранить массив Y-координат брейкпоинтов, вызывать колбэк при их прохождении (по времени или позиции).

**Проблема 5: Лишние ререндеры и лаги**
- Решение: Вся анимация — через requestAnimationFrame и useRef, не через React state.

**Проблема 6: Очищение ресурсов**
- Решение: Отменять animationFrame при размонтировании, очищать массивы частиц/линий.

**Проблема 7: Сложно отлаживать**
- Решение: Временно рисовать bounding box, логировать параметры, использовать разные цвета для разных линий.

## 12. Как полностью перенести эффект whirlwind на canvas

1. **Подготовить новый компонент WhirlwindSpinnerCanvas**
   - Создать компонент, который рендерит <canvas> с нужными размерами и стилями поверх игрового поля.
   - Настроить devicePixelRatio для четкости.

2. **Перенести генерацию данных**
   - Перенести функции генерации линий и клеток (цвета, параметры анимации) из LoadingSpinner/Line в useRef внутри нового компонента.
   - Для svg-цветов можно использовать либо прямоугольники, либо загрузить svg-иконки через Image и рисовать их на canvas.

3. **Реализовать анимацию**
   - В useEffect запускать requestAnimationFrame-анимацию.
   - На каждом кадре:
     - Очищать canvas.
     - Для каждой линии:
       - Вычислять прогресс (t) по времени.
       - Для каждой клетки:
         - Интерполировать параметры (позиция, масштаб, поворот, прозрачность) по keyframes (аналог motion.div).
         - Рисовать клетку (rect/arc/Image) с нужными трансформациями.
       - Проверять, прошла ли линия очередной брейкпоинт (строку) — если да, вызывать onLineBreakpoint.
     - Если все линии завершили анимацию — вызвать onFinish.

4. **Синхронизировать с логикой игры**
   - onLineBreakpoint — вызывать при прохождении очередной строки (аналогично motion-версии).
   - onFinish — вызывать по завершении всей анимации.

5. **Интегрировать компонент**
   - Заменить <LoadingSpinner ... /> на <WhirlwindSpinnerCanvas ... /> в GameBoard.
   - Передавать все нужные пропсы (width, height, onFinish, onLineBreakpoint).

6. **Проверить визуал и производительность**
   - Сравнить с оригиналом: цвета, траектории, масштаб, fade, взрыв.
   - Проверить на разных устройствах и разрешениях.

7. **(Опционально) Улучшить визуал**
   - Добавить glow/blur через ctx.shadowBlur, ctx.shadowColor.
   - Использовать offscreen canvas для сложных svg-иконок.
   - Добавить дополнительные эффекты (например, вспышки, искры).
